## 评估时必须处理的兼容问题（现已解决）

1. **启动器不接受 live 模式。** C 的 `start.ps1` 健康检查要求 `agent_mode == demo`。组合入口在配置模型后返回 `live`，临时探针已复现现有启动条件为false。应允许正常的demo/live模式并保持版本校验，而不是把真实模型服务判为启动失败。
2. **前端仍固定演示文案与类型。** `Conversation.mode` 只声明demo，智能体窗口固定显示“预设演示回复”；B实际可能返回live、notice和references。需按真实返回状态展示来源及失败降级提示，并明确本轮是否接入B新增的流式、识别和诊断入口。
3. **超时不一致。** 前端统一超时15秒，B默认模型超时30秒。慢响应可能已在后端保存，前端却报失败，用户重试可能生成重复记录。应为AI请求单独协调前后端超时并明确重试行为。

## 评估时发现的B模块待修正项（现已解决）

- `recognize_question` 只检查model_ready，不检查resolved_mode。用假配置及模拟模型客户端核验：AGENT_MODE=demo时仍调用识别模型并返回live。需落实演示模式不调用模型的约定；本次没有真实模型请求或费用。
- `step_feedback` 只要命中规则关键词就给出incorrect。已复现“可导必连续。”被判incorrect。应将关键词命中视为待复核提示，不能直接形成确定错误结论，并修改相应测试。
