## 二、逐条明细

### 1. 知识讲解重构：AI 拆解知识点 → 树状图

- **会议要求**：不直接输出长文本，先把题目拆成知识点，以树状图呈现。
- **现状（部分）**：
  - 提示词已要求"不要把例题的每一步都讲完：给出关键一步后停下来提问"（`backend/app/ai/prompts.py:19`）
  - 诊断接口能给出薄弱知识点与变式练习（`backend/app/ai/diagnosis.py`）
  - 前端原型里已有"知识树"的视觉示意（`未完工的极简UI/`）
  - **缺**：知识点之间没有**层级/依赖关系**的数据模型（知识库是 12 个平铺知识点，无 `parent`/`depth`），前端也没有真正的树图组件
- **落地建议**：给知识点补前置关系（或单独一张 `knowledge_edges` 表）→ 前端用 SVG 画树（原型里的参数曲线画法可直接复用）
- **验收标准**：问一道极限题，界面出现可展开的树状图；节点可点击、可跳过
- **风险**：层级是人工知识工程，12 个点够用，知识点扩展后维护成本上升
- **归属**：B（推理与结构输出）+ C（知识库 schema 变更需平台侧出迁移）

### 2. 教学逻辑：刻意练习 / 苏格拉底提问法

- **会议要求**：由易到难叠加条件，进度控制权交给用户，可跳过繁琐讲解。
- **现状（部分）**：
  - 已有"停下来提问"式引导（`prompts.py:19`）
  - 步骤批改**只判学生提交的那一步**、不提前给答案（`prompts.py:55-56`）
  - 推荐练习接口支持换一批（`/api/agent/recommend` 的 `exclude`）
  - 掌握度只用可核对证据计算，不靠模型判断（`backend/app/ai/insight.py`）
  - **缺**：难度递进没有参数化（无法显式请求"只给提示"或"给完整步骤"）；"跳过讲解"只是提示词里的软约束，没有产品化的跳过入口
- **落地建议**：`/api/agent/ask` 增加 `level`（0–3）与 `skip_hint` 参数；树节点上给"跳过 / 展开"按钮
- **验收标准**：同一道题能请求两档详略；每一层都能跳过
- **归属**：B

### 3. 章节处理：仅作后台索引，前台弱化

- **会议要求**：章节退到后台知识库索引，前台弱化，结合知识导图辅助自学。
- **现状（部分）**：
  - 教师端题库已按 12 章分组，章节数据在 `frontend/src/shared/courseChapters.ts`
  - **缺**：学生端"课程探索"仍是一级导航，前台没有弱化
- **落地建议**：学生端把"课程探索"降级进 More；章节继续作为后台索引；补一个知识导图作为自学入口
- **验收标准**：章节不再是学生的主路径；从知识点能反向定位到所属章节
- **归属**：A（学生端导航）+ C（章节数据）

### 4. Markdown 兼容（星号乱码）

- **现状（已有）**：2026-09-25 完成。新增 `frontend/src/shared/markdown.ts`（零依赖），`MathText.vue` 的非公式片段改走它；因 `MathText` 是公共渲染组件，Agent 回答、诊断、总结、复述一次性全部生效。见提交 `52e25cd`。
- **剩余**：表格、链接、嵌套列表未支持（按普通段落显示）
- **归属**：B（已完成）

### 5. 视频资源：外链跳转 + 官方推荐

- **会议要求**：内置无头浏览器 → 外链跳转全网视频，规避版权；"官方推荐 + 自主搜索"双策略。
- **现状（规划）**：前端与后端**都没有**视频、外链或浏览器相关实现（代码零命中）。
- **落地建议（分两步）**：
  1. **MVP（建议先做）**：按知识点维护一份"官方推荐"外链清单 + 一个跳转搜索的入口。不引入无头浏览器，零合规风险。
  2. **进阶**：无头浏览器抓取（成本与合规风险都高，建议明确不做或最后再做）
- **验收标准**：从某个知识点能进"相关视频"，点开在新标签播放外部链接
- **风险**：**版权与合规**是这条的红线——只跳转、不转载、不镜像
- **归属**：A（前端入口）+ C（资源配置）

### 6. 语音输入

- **会议要求**：新增语音导入功能。
- **现状（规划）**：代码零命中。
- **落地建议**：优先用浏览器原生 Web Speech API（零依赖、零后端改动）；若识别质量不够，再考虑录音上传 + 服务端 ASR
- **验收标准**：按住说话，松手后文字出现在输入框
- **风险**：中文识别准确率；**浏览器兼容性**（Chrome / Edge 可用，Firefox 不支持）
- **归属**：A（交互）+ B（若走服务端 ASR）

### 7. UI 自定义降级

- **会议要求**：搁置自由拖拽，改为**按钮删减 / 顺序调整 + 壁纸更换**。
- **现状（规划）**：代码零命中；但原型里已有完整交互示意（`未完工的极简UI/` 的 Setting → 页面与顺序，用 ↑↓ 按钮，不用拖拽）
- **落地建议**：按钮的显示与顺序用 `localStorage` 存偏好即可，**不需要后端**；壁纸直接复用 Own 的参数曲线生成器（零图片素材、自动适配深浅色）
- **验收标准**：能隐藏/显示功能入口、能调整顺序、能更换背景，且刷新后保持
- **归属**：A

### 8. 趣味联动：仅保留班级排行榜

- **会议要求**：只保留班级排行榜并**防刷量**；驳回游戏闯关、对战等过度趣味化。
- **现状（规划）**：代码零命中；`frontend/src/shared/classProgress.ts`（成员进度/CSV）可作为数据源
- **落地建议**：按**知识点掌握度**排序，而不是答题数量——掌握度只认可核对证据（`insight.py` 已实现该机制），刷题不涨分，天然防刷
- **验收标准**：学生能看到班级内相对位置，且重复刷同一题不会提升排名
- **风险**：**隐私**——排名会暴露同学姓名与学情，建议只显示昵称或做成可选匿名
- **归属**：C（班级模块）+ B（掌握度数据）

### 9. 操作效率：核心操作 ≤4 击

- **现状（验收标准，无代码可验）**：原型按此设计（主路径"选板块 → 选条目 → 操作"= 2–3 击）
- **落地建议**：写进每个功能的验收项；实现后在真机上逐条数一遍点击数，超 4 击的必须合并入口
- **归属**：全体

### 10. 师生联动

- **会议要求**：学生端（搜题学透）+ 教师端（发布作业）+ 班级模块（共同学习）。
- **现状（部分）**：
  - 教师端已有作业发布与班级管理，学生端有作业提交（C 的教师端 v0.3）
  - B 模块的诊断 / 推荐 / 掌握度可支撑"搜题学透"
  - **缺**：**班级共同学习**（讨论、协作）没有任何实现；教师端也还看不到"按知识点聚合的班级薄弱点"
- **落地建议（MVP）**：教师发布作业 → 学生完成 → 教师端按知识点看到班级薄弱点（复用 `insight.py` 的掌握度，按班级聚合）
- **验收标准**：教师发一份作业，学生做完后教师能看到"本班在哪几个知识点上薄弱"
- **归属**：全体（C 主导教师端，B 提供聚合数据）
- **备注**：按 `AGENTS.md`，按班聚合掌握度属于"明确未做"的能力，不在 main 上——本清单把它列为待做，不要对外宣称已有
