# 架构与决策

最后更新：2026-09-21。

当前将C教师工作空间v0.3/schema v3及精简界面与main 168928d拍照增量整合。仍为Vue 3 + TypeScript + Vite 6、Element Plus、KaTeX、ECharts与FastAPI + SQLAlchemy，无新增依赖或schema变更；按用户合并请求保留main已有两套原型目录及PCL.exe，不进入应用构建/启动。

此前已从建设计划书确认技术路线。PostgreSQL / pgvector、百炼、Tavily、SymPy、worker和Docker Compose属于正式路线而非全部已实现。当前默认SQLite，v3迁移拒绝非SQLite；真实外部模型效果未经验证，不能以兼容接口代替效果验收。

学生端与教师端调用后端接口；平台模块负责身份、权限、文件与持久化；教学模块负责题库、作业及复核；AI 模块负责识别、检索、诊断与学习策略。AI 输出通过平台保存，前端负责呈现，不直接调用需要秘密凭据的模型服务。已整合的拍照入口仍调用既有后端识别API，不在浏览器保存模型密钥。

后续目标：AI 返回圈注坐标和解释，学生端显示；AI 决定记忆更新策略，平台存储并控制访问；教师端提供 AI 反馈复核入口，AI 使用复核结果修正后续反馈。上述圈注/记忆/教师AI复核能力本版尚未实现；当前新增的教师人工评语只针对学生作答，不驱动 AI。

学生问答和 C 教师闭环均已打通：题库→草稿→发布→学生提交→教师按版本反馈→学生修改→教师复核→归档。B/C 已集成并通过 PR #2 合入 main。模型或演示来源均明确标记；本地假模型与固定演示内容不可作为真实模型效果或真实教学效果的证据。

## 当前实现

### 9/21 模拟验收与已知缺口

免费模型续测只在忽略.runtime放置官方Qwen3-VL-2B量化权重和llama.cpp独立工具，未加入应用依赖、默认启动或源码交付。应用沿用现有兼容接口连接本机18323，业务QA另用18324和新.tmp库。CPU短请求可返回真实答案，但带课程资料的普通问答和两张图识别超过现有60秒网络等待上限；这不是已通过的真实接入方案。Vulkan启动异常未定位，不修改驱动；收尾已停测试服务，具体参数/证据见报告。

本轮没有调整业务架构或schema，仅在既有tests/docs新增可复现验收资料。`check_simulation.py`只连接显式标记的本机demo实例，启动时仍必须另行确保DATABASE_URL指向隔离库；标记不能证明物理数据库隔离。`check_ai_contracts.py`拦截网络、dotenv读取、数据库连接和初始化，记录合成响应的实际问题而非真实模型通过率。

师生顺序闭环通过，但双端页面操作出现SQLite锁冲突/教师统计读取失败，需单独定位与修复，不能用82项现有回归通过代替并发稳定性。B知识库7点/2主题不等于题库12章覆盖；识别只返回suggested_topic，没有知识点详情或弹窗数据。先前模拟测试时本地无拍照组件；本轮合并已纳入该组件，建议知识点仍仅为主题标签。OCR入参和模型JSON校验缺口、缺配置阻塞及测试证据见[模拟验收报告](simulation-test-report.md)。

### 9/20 班级优先入口与章节题库

教师侧栏仅保留教学概览、班级管理、教学助手、账号设置。`ClassesView.vue`在班级列表、本班作业、独立成员页之间切换；`AssignmentsView.vue`嵌入班级页，仍供学生侧独立使用。所有作业从既有授权列表取得，班级内再做展示筛选；概览筛选只影响概览，不会让其他班级作业或未分班草稿丢失。保存后刷新数据，变更草稿目标班级时同步切换展示范围。

`QuestionBank.vue`改为作业编辑中的选题器，保留教师私有题目的新建/编辑/归档。`shared/courseChapters.ts`集中维护章节目录、旧章名前缀兼容、搜索/章节分组和追加题干规则。跨章选题保留选择与顺序，加入前重新读取有效题目；只追加标题/题干，不复制参考答案，不覆盖已填要求，最多30题且合并后不超过3000字符。取消选题保留作业表单，不自动创建草稿。题库维护本身仍会即时保存题目，取消作业不会撤销题库编辑。

章级目录参考同济大学数学科学学院《高等数学》第八版，高等教育出版社官方[上册目录（ISBN 9787040589818）](https://xuanshu.hep.com.cn/front/h5Mobile/bookDetails?bookId=62cdab46938b7cc2960eedb1)与[下册目录（ISBN 9787040588682）](https://xuanshu.hep.com.cn/front/h5Mobile/bookDetails?bookId=62bc8b97938b7cc2960eebb7)，2026-09-20核对。仅采用分类，不复制教材习题或宣称题目已获教材认证：

- 上册：1函数与极限、2导数与微分、3微分中值定理与导数的应用、4不定积分、5定积分、6定积分的应用、7微分方程。
- 下册：8向量代数与空间解析几何、9多元函数微分法及其应用、10重积分、11曲线积分与曲面积分、12无穷级数。

原有自定义topic保留且可继续维护，未新增数据表或批量回写。API授权、收件快照、提交/人工反馈和SQLite v3保持不变；章级目录不是B模块知识库复核，不改变BM25资料的verified状态。

### 9/21 成员设置与直接分章选题

ClassesView成员行通过单个设置按钮打开管理弹窗，账号操作继续受manageable约束。批量模式仅从当前可见列表取勾选成员，跳过已处于目标状态者；刷新、筛选或换页清空勾选，确认时固定班级ID、名单及目标状态。classProgress.ts集中实现目标筛选和逐人请求，首个失败停止、不重试、不回滚先前成功项，刷新名单并分别报告成功和未执行数量；归档班级不提供批量入口。沿用单成员PATCH和服务器授权，不新增批量API。

QuestionBank直接按教材章号1–12渲染有题目的章节分组，空章节不占列表，自定义章节排序置后，搜索保留分组顺序。不再有章节筛选前置步骤；新建/编辑题目仍需指定章节用于分类。作业表单移除章节选择但保留日期，topic由选题自动推导；跨章/已有不同章节内容合并为综合练习，手写默认综合练习，旧草稿非空topic不因打开保存而被改写。课程目录和参考答案隔离规则不变。

### 9/20 对话记录并入Agent

教师侧栏取消独立records项，AgentView聊天顶部和桌面最近问题区打开完整历史弹窗，复用RecordsView的embedded模式与原有搜索逻辑；支持全部/已收藏、刷新、选择记录回看，移动端不依赖被折叠的右栏。学生导航与独立记录/收藏组件保持兼容。发送/收藏请求期间锁定切换与新问题，避免异步响应覆盖刚选择的历史；打开历史不丢弃未发送内容。只使用既有Conversation列表/收藏接口，仍为独立问答，不声称多轮上下文或长期记忆。

### 沿用的平台与教学能力

- 页面：无教师空库先建档，已有账号登录后恢复工作台。教师有真实班级/成员、账号设置、按班概览/作业、题库、人工反馈与成员CSV导出；学生首登临时密码先改密，再访问本人收件作业、问答和历史。头像/姓名使用当前User，不再硬编码陈/林。
- 身份：默认不创建演示账号；首位教师通过一次性setup建立，可创建同级教师和所属学生。用户名唯一，新密码10–128位含英文字母数字，PBKDF2-HMAC-SHA256 260000次随机盐。HttpOnly/SameSite=Strict Cookie，库仅存token摘要；remember七天，否则八小时会话。临时密码限制业务访问，改密/重置撤销所有旧会话，停用账号拒绝认证。
- 请求：Vite将/api代理到FastAPI，写请求要求X-Requested-With，不开放CORS；浏览器不持有模型密钥。HTTPS需COOKIE_SECURE=true。当前仍缺正式身份、登录限流、统一管理员及公网部署保障。
- 数据：保留users/sessions/conversations/assignments/submissions/questions/reviews/schema_migrations，新增classrooms、class_members、assignment_recipients。默认backend/demo.db，名称兼容保留；教师资源归属、账号管理创建人、班级成员和作业收件人分别控制权限，不靠前端筛选。
- 问答：B模型兼容接口+本地BM25课程检索，未配置/调用失败时使用明确标注的固定示例；不做自动评分。收藏只是用户标记。图表仅统计实际记录，不推断掌握度。当前是单问题记录，不提供多轮推理上下文。
- 作业：draft→published→archived。草稿可不完整/未选班；发布须选本人未归档且含有效学生的班级，保存收件快照。后加成员不会自动收到旧作业，退班仍能读自己的历史但不可提交。发布后题干/班级锁定，仅延期；作业归档不可逆。复制不带提交/反馈，源班归档则新草稿class_id=null。题库复制不泄露参考答案。
- 反馈：学生保存作答递增 version；review 唯一对应 submission_id + version，保留 answer_snapshot。当前版本无反馈即待批改；学生修改不沿用旧结论。教师提交版本过期返回409。同版评语允许修改，旧版反馈保留。SQLite 写事务使用 BEGIN IMMEDIATE，使状态检查和写入串行化；截止当天可提交，归档后提交/批改均409。
- 统计：总览仅当前教师有效班级的已发布作业，按收件快照计算应交/未交，当前反馈分待批改/待改进/已完成；有效学生按活跃账号/成员去重。班级名册可查归档班级的历史进度，导出当前筛选结果。不读取私人问答，不推断掌握度。
- CSV：`shared/classProgress.ts`集中实现当前列表筛选、安全序列化和下载；页面与导出共用筛选结果。UTF-8 BOM与引号转义保留中文/逗号/多行，公式及前导空白风险加文本前缀；下载链接挂载后点击、移除，延后1秒释放对象URL。原生Node测试覆盖内容与清理顺序，不替代真实浏览器落盘/Excel验收。
- 初始化与迁移：upgrade先备份再BEGIN EXCLUSIVE升级到v3，失败回滚不启动；历史每位教师建立班级并保留旧可见范围，单教师旧库才推定学生账号管理归属。多教师归属不明以manageable=false展示。当前v3重启校验表/列；显式种子仅在空用户表执行，不重建被修改账号/作业。restore验证并恢复到新路径，拒绝覆盖。
- 本地运行：根目录一键启动.cmd 调用 start.ps1；默认由 bootstrap.ps1 在项目 `.runtime` 内下载并校验固定 Python/Node/pip、安装锁定依赖、构建前端，再由单个 FastAPI 进程同源提供页面/API。重复运行复用本目录服务，目录锁防止并发启动，端口不可用时自动换端口；支持 -SetupOnly、-NoBrowser、-Port。-Dev 才使用系统开发环境的8000/5173热更新。当前没有公网部署、Docker Compose 配置或 CI 工作流。

## 2026-09-18 / Windows便携测试分发

## 智能体（B）处理流水线（2026-09-17 追加）

目的：把“演示问答”升级为可接真实模型的骨架，同时保证没有模型密钥时流程仍然完整、且不把预设文案冒充模型输出。

流水线：

1. **配置**：`backend/app/ai/config.py` 读取 `AGENT_MODE` 与 `MODEL_*`，得出 `resolved_mode`（`demo` / `live`）；`live` 缺凭据时如实降级为 `demo`。
2. **检索**：`knowledge.py` 对 `KNOWLEDGE_POINTS` 建本地 BM25 索引（中文按字 bigram），返回带出处（`source`）与命中词（`matched`）的片段，因此引用可解释、可复核。
3. **提示词**：`prompts.py` 组装分层提示（概念层 → 例题层 → 迁移层），要求只依据片段作答并在句末标注 `[n]` 编号。
4. **调用**：`llm.py` 用 httpx 调 OpenAI 兼容 Chat Completions（含流式），把失败统一翻译成 `ModelUnavailable` / `ModelCallFailed`。
5. **组装与降级**：`service.py#compose_answer` 决定走 live 还是 demo；模型失败时回退 demo，并在 `notice` 里写明原因。
6. **诊断与步骤反馈**：`diagnosis.py` 规则用于产生可追溯的候选薄弱点和自检提示；启发式 confidence 未经效果校准。demo 下步骤 verdict 统一为 `unclear`，不能因关键词直接判错；live 模式模型判断也必须由教师或学生复核。

模块边界：B 只产出结构化结果，不实现权限与持久化；鉴权与存储仍走 `platform`（C）。B 未新增数据库列，历史记录的 `mode` 由答案文本中的演示标记反推。

升级路径：把 `knowledge.retrieve()` 换成向量检索、把 `llm.chat()` 换成多模型路由，都不需要改动路由层与前端。

## 长期记忆与学情洞察（B 第二阶段，2026-09-21 追加）

目的：第一阶段只解决“一次问答/一次反馈”，第二阶段要让智能体记得学生练过什么、薄弱在哪，并把结论用于推荐与复习。

数据流：

1. **证据产生**（全部可核对，不含模型判断）：
   - `/api/agent/review` 的复述/自评结果（`band` → 权重 +1 / -1 / -2）；
   - `/api/agent/feedback` 的步骤反馈结论（`incorrect` → -1，`correct` → +1，其余 0）；
   - `/api/agent/diagnosis` 命中的薄弱知识点（每个 -1）；
   - `/api/conversations` 只记 `exposed`（权重 0，表示“问过”，不代表掌握）。
2. **存储**：追加式事件表 `ai_learning_events`。表由 `backend/app/ai/memory.py` 用独立 `MetaData` 惰性建（`create_all(checkfirst=True)`），
   **故意不进 `Base.metadata`**，原因是 `migrations/upgrade.py` 在 schema v3 会逐张校验 Base 的表是否都存在，加表会导致既有库启动失败。
3. **聚合**：`memory.state()` 在读取时按知识点聚合，得到掌握度（拉普拉斯平滑加权成功率）、`confidence`（证据量）、`status`、`last_seen`。
4. **消费**：
   - `insight.recommend()` 按 `weak → learning → unseen` 排序给练习，`exclude` 支持“换一批”；
   - `insight.evaluate()` 按知识点 `signals` 覆盖率给出评价档位与缺失项；
   - `insight.summarize()` 汇总窗口内提问记录与记忆薄弱项，给出 `highlights` 与 `next_steps`。

边界与取舍：

- 掌握度不是模型输出；证据不足时状态为 `unseen`，宁可不说“已掌握”。
- live 模式下模型只润色总结或补充点评（`model_comment` / `model_summary`），规则结论保留原样并在 `method` 里写明。
- 记忆只对本人开放，可自行清空；教师端按班聚合属于后续工作，需要先定权限边界。
- 若日后要把记忆纳入版本化 schema，需平台侧出 v4 迁移并同步 `docs/contracts`。

## 界面主题（浅色 / 深色，2026-09-21 追加）

主题是纯前端表现层能力，不影响接口、数据与模块边界。

- 状态：`frontend/src/shared/theme.ts` 管理 `light` / `dark` / `system`，持久化在 `localStorage`（`shuban-theme`），并监听系统配色变化；实际渲染通过 `<html class="dark">` 生效。
- 防闪烁：`frontend/index.html` 的内联脚本在 Vue 挂载前读取偏好并设置类名与 `color-scheme`。
- 深色规则：由 `build-dark-theme.py` 从 `frontend/src/shared/style.css` 与各组件 `<style>` 块推导，输出 `frontend/src/shared/dark-theme.css`。选择器一律带 `html.dark` 前缀，浅色模式不读取该文件；生成器带有守卫，一旦有选择器逃出 `html.dark` 作用域即中止。
- 组件层：叠加 Element Plus 官方深色变量（`element-plus/theme-chalk/dark/css-vars.css`）。
- 边界：不做主题服务端同步、自定义配色或图片深色变体；配色调整后需重新运行生成脚本并重建前端。
