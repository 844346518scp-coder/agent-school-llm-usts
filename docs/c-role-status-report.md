## C 的职责边界

C 负责平台基础、教师端和集成协调，包括：

- `backend/app/platform/`：认证、会话、数据模型和持久化基础。
- `backend/app/teaching/`：班级、成员、学生管理、题库、作业、提交、教师反馈、统计和资源权限。
- `frontend/src/teacher/`：教师概览、班级管理与题库；共享账号设置/登录、作业/反馈页面需联动。
- 共享作业/反馈页面、`backend/app/main.py`、数据库迁移、公共接口、依赖、启动交付和跨模块回归由 C 统筹。
- A 负责学生端交互与反馈展示；B 负责模型、OCR、检索、诊断、推荐和记忆策略。C 为这些能力提供权限、持久化、教师复核和稳定接口，不替代 A/B 决定其业务策略。

A/B 负责人和公共文件复核人仍待团队确认。公共接口、数据库和共享文件变更应先协调，不能覆盖其他成员未完成的修改。

## 本轮 v0.3 增量与使用规则

| 范围 | 当前实现范围与约束 |
|---|---|
| 首次使用 | 空库只允许一次创建第一位教师；不默认创建公开账号/作业。显式演示种子仅用于演示/回归 |
| 账号 | 教师创建同级教师和自己管理的学生；新建学生/同级教师首次改密。改密/重置撤销会话，停用立即禁止登录 |
| 班级 | 本教师创建、编辑、归档/恢复；成员加入/移出与账号停用是不同操作，均保留历史 |
| 作业授权 | 选择本人有效班级，至少一位有效学生才可发布；按发布时收件快照授权，新增成员不自动获得旧作业 |
| 只读边界 | 退班/班级归档后不能提交；班级归档后不能写教师反馈。作业归档不可逆，班级归档可恢复 |
| 统计与导出 | 概览与班级进度读取真实人数、应交、已交、未交及人工反馈；CSV仅导出所选班级当前搜索/成员状态筛选结果，不读取学生私人问答；落盘兼容仍待补验 |
| 旧库兼容 | schema v3迁移前备份，历史班级保留旧可见范围。仅单教师旧库可推定学生账号管理归属；多教师旧库不擅自授予账号重置权 |

源班级未归档时复制保留班级；源班级归档时新草稿不选班，重新选择有效班级后发布。发布后的题干/班级不能更改，历史数据不被重新归属。

## 当前限制

- 本地账号创建/停用/重置不等于正式身份体系；没有批量导入、单点登录、统一管理员、登录限流或自行找回密码流程。
- 每班只有一位归属教师，课程和学期是班级标签；没有助教、共同授课、跨教师学生共享及转移账号归属界面。历史多教师账号归属不明时，只允许班级成员维护，不允许账号重置。
- 当前仅支持SQLite；PostgreSQL驱动存在不等于已支持，schema v3迁移拒绝非SQLite。
- 当前教师反馈全部是人工反馈。AI 步骤反馈/诊断接口尚未形成“AI 原结果→教师修改→批准发布→学生查看”的复核链路。
- 远端main已有拍照搜题前端入口，但只有TypeScript/Vite构建记录，缺真机相机、后端401/502/503联调和真实视觉模型验证；当前工作区没有该组件。独立“AI视频解析”原型缺少对应后端接口，不是正式能力。
- 没有课程资料上传、向量检索、异步任务、语音、自动评分、操作审计、CI、定时备份或公网部署。
- 本地假模型、规则结果和固定演示回复均不能作为真实模型或真实教学效果证明；另一台 Windows 实机也尚未验收。
