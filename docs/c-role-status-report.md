项目已具备“数伴 0.1 本地 MVP”，可以演示学生提问与记录保存、教师发布作业、学生提交、教师查看作答。真实 AI 尚未接入，当前也不是可直接上线的正式教学平台。你已认领 C：平台基础、教师端和集成协调；无需从零重建现有功能。

## 你需要做的工作（建议顺序）

| 优先级 | C 的任务 | 最小验收标准 |
|---|---|---|
| P0：先对齐 | 与 A/B 约定用户、班级、题目、作答、诊断、复核的数据字段与接口；统筹公共文件、依赖和 PR 集成 | 接口文档写清输入输出、权限、错误和任务状态；A/B 可按约定独立开发。 |
| P0：平台底座 | 正式账号创建/导入、重置与停用；班级、成员、教师归属及资源权限 | 使用至少两个班级验证：学生不能查看或提交别班作业，教师不能访问无授权班级数据。 |
| P0：数据可靠性 | 验证 PostgreSQL，建立版本化迁移；与 B 配合落实 pgvector 所需存储 | 新库可初始化、旧库可升级；保留原记录并验证备份恢复。SQLite 数据迁移需明确方案。 |
| P1：教师业务 | 题库与课程资料管理、按班级布置作业、查看提交、教师复核入口与基础学情统计 | 跑通“发布→提交→复核→学生看到反馈”；统计有真实数据依据，复核保留原结果与修改记录。 |
| P1：支撑 B 接入 | 文件上传与访问权限、诊断任务状态、结果/引用/记忆证据存储 | 上传可控、任务失败可见、结果可追溯；记忆更新和诊断策略由 B 决定。 |
| P2：交付保障 | 审计、异常排查、备份恢复、部署配置、权限回归与自动化检查 | 新环境按文档能启动，关键流程与越权测试通过，备份实际恢复成功后再安排正式部署。 |

建议第一项具体开发任务：先写账号与班级数据/接口方案，再实现班级权限。现有学生作业查询未按班级过滤，新增真实用户前必须补齐这一层。
